ClipMux is built for teams that need hosted video infrastructure without inheriting the cost profile of products like Mux or Cloudflare Stream. The goal is simple: make video ingestion, processing, playback, and delivery feel like a clean developer workflow instead of a black box.

## What ClipMux Does

At a high level, ClipMux helps you:

- upload source video files
- process them into playback-ready outputs
- serve those outputs through a global delivery layer
- control access with signed or public playback rules
- integrate the experience into your own product, UI, and backend

The platform is focused on VOD use cases first. Live streaming, advanced analytics, and richer workflow automation can come later, but the current foundation is built around reliable hosted video-on-demand.

## Core Concepts

### Assets

An asset is the canonical video object inside ClipMux. It begins as an uploaded source file and becomes the reference point for processing status, playback metadata, and delivery configuration.

### Processing

After ingestion, ClipMux can analyze and transcode the source into formats suitable for streaming playback. This stage is where a raw upload becomes a usable media asset for web and app experiences.

### Playback

Playback is the consumer-facing side of the platform. Once an asset is ready, ClipMux can expose a playback URL, manifest, or signed access path that your player uses to stream the content.

### Delivery

Delivery is responsible for getting the right media segments to viewers quickly and consistently. In practice that means cache-friendly output, edge delivery, and access controls that are compatible with real production traffic.

## Upload and Processing

The intended ClipMux workflow looks like this:

1. Your app creates or requests an upload target.
2. The source file is sent to ClipMux storage.
3. A processing pipeline prepares the asset for playback.
4. Your backend or frontend retrieves playback details when the asset is ready.

This model is designed to work for both dashboard-driven workflows and fully custom product flows where your own application owns the UI and business logic.

## Playback and Delivery

For playback, ClipMux is designed around the same practical concerns teams care about on larger platforms:

- fast startup time
- adaptive delivery
- controlled access
- predictable URLs and playback identifiers
- straightforward player integration

The exact delivery model can evolve, but the direction is consistent: ClipMux should provide a secure playback layer that is easy to consume from your application code and efficient to serve globally.

## API-First by Default

The platform is being shaped for developers first. That means the API surface matters as much as the dashboard:

- backend services should be able to create and manage assets programmatically
- frontend apps should have safe, limited ways to initiate upload flows
- SDKs should reduce ceremony around upload and playback integration
- webhook-style events should fit naturally into existing product workflows
