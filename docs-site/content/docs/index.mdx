ClipMux is open-source video infrastructure you run on your own accounts. Paste
Cloudflare R2 credentials and a Modal API key, and you get Mux-style HLS/DASH
ingestion: multipart uploads, GPU transcoding with adaptive-bitrate ladders,
signed playback URLs, AI subtitles and chapters, tenant webhooks and analytics.

**No vendor in the middle.** No metered SaaS, no per-minute billing, no hosted
API that can change under you. Apache-2.0, and the whole thing is this repository.

## The shape of an integration

Three packages, split by where the code runs:

| Package | Runs in | What it is for |
| --- | --- | --- |
| [`@clipmux/server`](https://www.npmjs.com/package/@clipmux/server) | Your backend only | Mints upload and playback tokens, manages videos, verifies webhooks. Holds the API key. |
| [`@clipmux/uploader`](https://www.npmjs.com/package/@clipmux/uploader) | The browser | Windowed multipart uploads with progress, pause/resume and typed errors. |
| [`@clipmux/player`](https://www.npmjs.com/package/@clipmux/player) | React 18/19 in the browser | HLS/DASH playback with signed-token auto-refresh, chapters and subtitles. |

The API key never reaches a browser. The browser gets short-lived tokens and
talks to **your** R2 bucket directly — video bytes never pass through the API.

```ts
// Your backend — the API key stays here.
const token = await vod.uploads.createToken({ expiresIn: '1h', maxFiles: 1 })
```

```ts
// The browser — uploads straight to your storage.
const result = await new ClipMuxUploader({ baseUrl, uploadToken }).upload(file, {
  onProgress: (p) => setProgress(p.percentage),
})
```

## What you are responsible for

ClipMux is infrastructure, not a service. Three things are yours to run, and the
docs say so plainly rather than burying them:

- **Delivery is always a Cloudflare Worker in front of R2.** It is not a default
  that a flag changes — there is no Node delivery path.
- **Object storage is always Cloudflare R2.** Generic S3 and MinIO are not
  implemented.
- **`@clipmux/player` is React-only.** The same manifests play anywhere with
  hls.js or a native `<video>` tag; see the
  [integrations matrix](/integrations#the-matrix).

Everything else — API runtime, Postgres transport, transcode provider, dispatch,
rate-limit store — is a documented choice. See
[Configuration](/configuration) and [Deployment](/deploy).

## Why ClipMux

- **Bring your own keys.** Storage, compute and database are yours. Nothing is
  metered by us because there is no us.
- **Mux-style DX.** Upload tokens, typed transcode callbacks, signed playback,
  webhooks with signature verification. The mental model transfers.
- **Honest contracts.** Stable error codes, at-least-once webhooks you can
  de-duplicate on, and a health endpoint that reports the deployment's actual
  shape instead of a version string.
