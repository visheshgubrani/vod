ClipMux has one codebase and two stacks. Local development runs Postgres and
Redis from `docker-compose.dev.yml` with the API and dashboard on the host
(`pnpm dev`). A **deployment** is `docker-compose.yml`, configured by `.env` at
the repo root. The API always runs on Node.

**Operators installing on a host or VPS should run
[`scripts/install.sh`](/host-install)** rather than copying `.env.example` by
hand. This page is the Compose shape, maintenance and recovery once that stack
exists.

Signed playback is always the **Cloudflare delivery worker** in front of R2. That
is fixed, not a default.

<Callout type="info" title="Not sure which shape you want?">
  [Quickstart](/quickstart) walks both paths end to end. Come back here for the
  operational detail — maintenance, recovery, and what refuses to boot.
</Callout>

## Path A — Docker Compose

Runs the API, dashboard, Postgres and Redis. Requires a Cloudflare delivery worker
deployed separately.

```bash
cp .env.example .env      # secrets, public URLs, R2 buckets — never commit it
pnpm docker:migrate       # one-shot migrate service (profile "tools")
pnpm docker:up            # docker compose up -d
```

- API on `http://localhost:8787`, dashboard on `http://localhost:3000`, both
  bound to `127.0.0.1`. Put a reverse proxy in front for public traffic.
- Postgres and Redis are internal to the stack with no host port. Set
  `DATABASE_URL` / `REDIS_URL` in `.env` to point at your own servers instead.
- `NEXT_PUBLIC_*` values are baked into the web image at build time. Changing one
  means rebuilding the image.
- `pnpm dev` and `docker compose up -d` both want ports 8787 and 3000. Run one or
  the other, not both.

**The Compose stack has no delivery service** — there is no Node delivery path.
Deploy `delivery/` to Cloudflare regardless of which shape you choose.

## Path B — Cloudflare delivery worker

The API is Node. Deploy only the delivery worker to Cloudflare:

```bash
cd delivery
pnpm exec wrangler secret bulk <secrets.json>   # JWT_SECRET, ANALYTICS_INGEST_SECRET, ANALYTICS_ENABLED
pnpm exec wrangler deploy
```

The dashboard goes wherever Next.js runs — Vercel, the Docker web image, or a
Node host. Set its `NEXT_PUBLIC_*` values to your deployed API.

<Callout type="warn" title="Modal cannot reach localhost">
  `BACKEND_URL` is the API's own **public** origin, and the transcode callback URL
  is built from it. If it points at `localhost`, Modal's cloud cannot deliver the
  callback and videos strand in `processing` forever while the database never
  flips to `ready` or `failed`. For local development against real Modal, expose
  the API with a tunnel and point `BACKEND_URL` at it.
</Callout>

## What varies, and what does not

| Axis | Options | Selected by |
| --- | --- | --- |
| Postgres | bundled \| any `postgresql://` URL | `DATABASE_URL` |
| Transcode provider | `modal` \| `local` | `TRANSCODE_PROVIDER` |
| Dispatch transport | `direct-http` \| `qstash` | `QSTASH_TOKEN` presence |
| Rate-limit store | `memory` \| `redis` (TCP) \| `upstash` (REST) | `REDIS_URL` → Upstash REST → in-memory |
| Analytics write | `delivery-worker` \| `none` | `ANALYTICS_ENABLED` plus `DELIVERY_URL` and `ANALYTICS_INGEST_SECRET` |
| Analytics read | `cloudflare-sql` \| `none` | `ANALYTICS_ENABLED` plus `ACCOUNT_ID` + `CLOUDFLARE_ANALYTICS_TOKEN` |

**Fixed:** delivery is the Cloudflare Worker + R2, and object storage is
Cloudflare R2. Generic S3 and MinIO are not implemented.

`GET /health/config` reports exactly which of these your running deployment
resolved to — see [the health endpoint](/api-reference#get-healthconfig).

### Combinations that refuse to boot

| Combination | Why it is fatal |
| --- | --- |
| An unrecognised `TRANSCODE_PROVIDER` | The API refuses to boot rather than guess which provider should receive new jobs. |

## Profiles and services

| Service | Profile | How to run it |
| --- | --- | --- |
| `api` | default | `pnpm docker:up` |
| `web` | default | `pnpm docker:up` |
| `postgres`, `redis` | default | internal only, no host ports |
| `migrate` | `tools` | `pnpm docker:migrate` |
| `transcoder` | `transcoder` | Setup enables this only for `TRANSCODE_PROVIDER=local`; Modal does not build or start it |
| `caddy` | `proxy` | host installer preserves `proxy` and adds `transcoder` only for local encoding |

## Migrations

```bash
pnpm docker:migrate       # a deployment
pnpm db:migrate           # development
```

The `api` container also migrates on boot, but that races when you run more than
one replica — the one-shot service is the right call in production.

<Callout type="error" title="db:push is not a substitute">
  `db:push` cannot create the hand-written cleanup trigger, so the schema is
  subtly wrong in a way nothing catches until a video is deleted. Always
  `db:migrate`.
</Callout>

## Transcoding

Two deployment providers share one processing engine:

- **Modal GPU** — deploy `main.py` in `transcoding/`; the setup wizard uploads
  the required Modal secrets and refreshes callback hosts.
- **Local worker** — the setup wizard defaults fresh installs to one Compose
  worker, shares `LOCAL_TRANSCODER_SECRET` between API and worker, and waits for
  its heartbeat. No pairing or organization membership is needed.

`TRANSCODE_PROVIDER` applies to new jobs and is recorded when each job is
created. Existing work is never rerouted. `LOCAL_TRANSCODE_ENABLED=false`
rejects new local submissions while accepted local jobs drain. Before a managed
local-to-Modal switch, setup checks for queued or active local work; the Modal
profile does not build or start the local media image.

## Delivery worker

`wrangler deploy` in `delivery/`. It:

- verifies HS256 playback JWTs per request for signed content,
- rewrites every URI-bearing HLS/DASH tag, never foreign-host URLs,
- serves `206` range requests,
- meters bandwidth into Analytics Engine,
- cache-tags signed segments.

`DEFAULT_POLICY=signed` sets the fallback playback policy for the worker. Add your
custom domain after deploying — the shipped config contains commented examples,
not live hostnames.

<Callout type="error" title="JWT_SECRET must match on both sides">
  The API signs playback tokens and the delivery worker verifies them with the
  same HS256 secret. A mismatch makes every signed video fail with a `401` that
  looks like an auth bug in your app. One value, two places.
</Callout>

## Maintenance and recovery

Without maintenance, two things silently stop: **webhook retries** and **storage
reclamation**. Deleted videos keep their bytes in R2 and failed deliveries are
never retried.

| Runtime | What runs the sweep |
| --- | --- |
| Node API (default) | In-process scheduler after listen when `SWEEP_ENABLED=true` |
| Additional replicas | Set `SWEEP_ENABLED=false`. Manual sweeps target the designated instance |

```bash
curl -X POST http://localhost:8787/api/internal/sweep \
  -H "x-sweep-secret: $INTERNAL_SWEEP_SECRET"
```

The sweeper is heartbeat-aware: a `processing` job stale for more than 45 minutes
is retried up to 3 times, then fails with a typed `JOB_TIMEOUT`. Abandoned
`uploading` rows are cleaned up separately.

`GET /health/config` reports `maintenance.enabled` **and** `maintenance.stale`.
Stale means the flag is on but no pass has succeeded recently — the exact silent
failure worth alerting on.

### Health probes

| Probe | Returns |
| --- | --- |
| `GET /health` (API) | Plain text `ok`. Use for liveness. |
| `GET /health/config` (API) | Capability flags, deployment shape, maintenance status. Secret-free. |
| `GET /health` (delivery worker) | Liveness for the delivery worker. |
| `GET /health/config` (delivery worker) | Capability flags: analytics enabled, ingest secret configured. Secret-free. |
| `GET /healthz` (Modal) | Liveness for the transcode endpoint. |

## Environment

Every variable, grouped, with the development-versus-deployment file split and the
fatal combinations, is on [Configuration](/configuration). The short version:

- **Development:** `server/.dev.vars`, loaded via `load-local-env.ts`.
- **Deployment:** `.env` at the repo root, read by Compose.
- **Delivery worker:** `cd delivery && pnpm exec wrangler secret put` /
  `wrangler secret bulk`. Never a committed file.
